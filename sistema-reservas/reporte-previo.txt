Tipo: Main / View (bootstrap, JFrame contenedor de tabs)
Hereda de: JFrame
Implementa: ninguna

Imports del proyecto:
  - controller.* (los 9 controllers)
  - logic.Service
  - model.* (7 de los 10 models: Actividades, Calendarizacion, CambiarClave,
             Categorias, Estadisticas, Funcionarios, Recursos, Reservas)
  - util.Sesion

Campos relevantes:
  - JTabbedPane tabs
  - static final Color BACKGROUND_ERROR (usado por casi todas las views para
    marcar campos inválidos — acoplamiento visual global)

Métodos públicos:
  - ApplicationLogin() (constructor, arma los 7 MVC de tabs + botones)
  - static void main(String[] args)

Notas: Instancia TODOS los MVC triads (View+Model+Controller) de las 7
pantallas con tab (Funcionarios, Categorias, Recursos, Reservas,
Calendarizacion, Actividades, Estadisticas) incondicionalmente en el
constructor, y luego decide cuáles tabs mostrar según el rol. Es decir, un
FUNCIONARIO también instancia FuncionariosController/CategoriasController/
RecursosController aunque nunca vea esos tabs. Los botones "Cambiar Clave" y
"Cerrar Sesion" crean un CambiarClaveView/Model/Controller y un nuevo
LoginView/Model/Controller respectivamente, de forma inline (ver flujos).

5. ApplicationLogin (equivalente a MenuPrincipalView) — ANÁLISIS CRÍTICO
════════════════════════════════════════════════════

No existe una clase MenuPrincipalView; ApplicationLogin (extends JFrame)
cumple ese rol además de ser la clase de arranque (contiene public static
void main()).

¿Cómo se abre cada pantalla?
  Las 7 pantallas con tab (Funcionarios, Categorias, Recursos, Reservas,
  Calendarizacion, Actividades, Estadisticas) NO se "abren": se construyen
  todas de una vez en el constructor de ApplicationLogin
  (new XxxView(); new XxxModel(); new XxxController(view, model);) y su
  view.getPanel() se agrega al JTabbedPane según el rol. No hay lazy
  loading — las 7 se instancian siempre, aunque el rol solo vaya a mostrar
  un subconjunto.
  Las pantallas modales (CambiarClaveView, LoginView) sí se abren bajo
  demanda con `new` + `setVisible(true)` dentro de ActionListeners.

¿Recibe services por constructor o los instancia adentro?
  Ninguno de los dos exactamente: ApplicationLogin no recibe ni instancia
  Service directamente para las pantallas de tab (eso lo hacen los
  Controllers vía Service.instance(), un singleton estático global). El
  único uso directo de Service en ApplicationLogin es
  Service.instance().stop() al cerrar la ventana (persistir a XML).

¿Cómo diferencia tabs de admin vs funcionario?
  switch (Sesion.getUsuario().getRol()) { case ADMIN: ...; case FUNCIONARIO: ...; }
  ADMIN ve: Funcionarios, Categorias, Recursos, Calendarizacion,
            Actividades, Estadisticas (6 tabs)
  FUNCIONARIO ve: Reservas, Calendarizacion, Actividades, Estadisticas (4 tabs)
  Nótese que FuncionariosView/CategoriasView/RecursosView/ReservasView se
  instancian TODAS igual sin importar el rol, aunque solo se muestre el
  subconjunto correspondiente vía tabs.addTab(...).

Lista cada botón/tab y qué controller abre:
  Tab "Funcionarios"     → FuncionariosController   (solo ADMIN)
  Tab "Categorias"       → CategoriasController      (solo ADMIN)
  Tab "Recursos"         → RecursosController        (solo ADMIN)
  Tab "Reservas"         → ReservasController        (solo FUNCIONARIO)
  Tab "Calendarizacion"  → CalendarizacionController (ambos roles)
  Tab "Actividades"      → ActividadesController     (ambos roles)
  Tab "Estadisticas"     → EstadisticasController    (ambos roles)
  Botón "Cambiar Clave"  → crea CambiarClaveController inline (ambos roles)
  Botón "Cerrar Sesion"  → Sesion.logout() + dispose() + doLogin() (que crea
                           LoginController) + si login exitoso, nueva
                           ApplicationLogin()

   NO se abre automáticamente (no hay llamada a Desktop.open ni similar);
   el usuario debe abrirlo manualmente desde el explorador de archivos.
